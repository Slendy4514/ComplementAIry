## Módulos

- `.devcontainer/post-attach.sh`: Script que se ejecuta al conectar VSCode en el contenedor; instala o actualiza la extensión de ComplementAIry desde el archivo `.vsix`. Depende de que la extensión compilada exista en `packages/vscode-complementairy/` y de tener acceso al comando `code-server`.
- `.devcontainer/post-create.sh`: Configura el contenedor al crearse: ajusta permisos de volúmenes, instala dependencias de pnpm, restaura historial de Claude y compila la CLI y extensión de ComplementAIry. Depende de los directorios de volúmenes, Node.js y pnpm.
- `devcontainer-feature/complementairy/install.sh`: Feature que instala la CLI de ComplementAIry a nivel global y prepara la extensión de VSCode. Depende de Node.js 20+ (se recomienda 22+), npm y los archivos `.tgz` y `.vsix` empaquetados en la feature.
- `examples/demo-ts/eslint.config.js`: Configuración de ESLint que aplica reglas recomendadas de JavaScript y TypeScript estricto. Depende de los paquetes `@eslint/js` y `typescript-eslint`.
- `examples/demo-ts/src/cuota.ts`: Función que calcula la cuota mensual de un préstamo usando el sistema francés; retorna el monto fijo por mes o el monto dividido si la tasa es cero. Sin dependencias externas.
- `Files.js`: Clase que abstrae operaciones con archivos/carpetas en Obsidian (`exists`, `ensureFolder`, `moveTo`), usando un helper privado `normalize` que valida rutas y un `selfTest` para verificación. Depende de la API de Obsidian (`window.app`) y gestiona colisiones de nombres sin sobrescribir.
- `packages/complementairy/src/acompanante.ts`: Orquestador que acompaña al programador en cada guardado: expande snippets marcados, responde preguntas pendientes, propone planos, detecta errores persistentes y ofrece ayuda cuando se traba. Mantiene estado persistente por archivo y articula decisiones deterministas (errores, vacío, falta plano) delegando redacción a la IA, dependiendo de 18+ módulos internos (biblioteca, contexto, métricas, perfil, render, ocupado, threads, tutor).
- `packages/complementairy/src/adapters.ts`: Define adaptadores (datos) para TypeScript/JavaScript y Python: especifica qué herramientas usan (tsc, ESLint, pytest, Stryker) y cómo parsear su salida. No tiene lógica; es una fuente de verdad para detectar stacks y ejecutar verificaciones.
- `packages/complementairy/src/arquitectura.ts`: Crea documentos ADR (Architectural Decision Records) en docs/adr/ con preguntas y opciones sugeridas por la IA, para que el humano complete con su decisión y justificación. Depende de config, context, llm, profile, tutor y verify.
- `packages/complementairy/src/bash.ts`: Define y valida reglas de seguridad para comandos Bash que ejecuta la IA, bloqueando instalación de dependencias, commits de git, edición de archivos y otras operaciones que requieren decisión del humano. No tiene dependencias externas.
- `packages/complementairy/src/biblioteca.ts`: Carga y gestiona una biblioteca de snippets reutilizables desde proyecto, usuario y base; permite expandirlos dinámicamente en archivos fuente con argumentos personalizables cuando el humano los solicita. Depende de comments, lang, profile, render y snippets.
- `packages/complementairy/src/cli.ts`: Punto de entrada de la herramienta cai que interpreta comandos de línea de comandos (init, hook, guia, expandir, snippet, revisar, gate, tests, panorama, etc.) y los enruta a sus respectivos módulos. Depende de: config, files, profile, state, hook, init, guia, tutor, watch, acompanante, plano, verificar, servir, modos, rapida, dialogo, tests, panorama, ocupado, responder, notas, siguiente, conocer, snippets, biblioteca, review, gate, predict, doctor, terminal, arquitectura.
- `packages/complementairy/src/comments.ts`: Define tipos e interfaces para representar comentarios en código fuente (Comment, Parsed, CommentKind) y proporciona funciones para extraer, clasificar y procesar comentarios en múltiples lenguajes. Depende de módulos de lenguajes (lang.js) y parser (parser.js) para analizar la sintaxis según el tipo de archivo.
- `packages/complementairy/src/config.ts`: Define el esquema de configuración del proyecto (.cai/config.json) con opciones para zonas, snippets, acompañante, modos de trabajo, prácticas medibles y autería; proporciona utilidades para cargar la config, determinar zonas del código y clasificar origen del código (propio, heredado o terceros). Depende de: fs, path, picomatch.
- `packages/complementairy/src/conocer.ts`: (sin resumen)
- `packages/complementairy/src/context.ts`: Carga y gestiona el contexto del proyecto desde archivos legibles (.cai/proyecto.md, .cai/reglas.md, reglas scoped) y memoria de errores frecuentes del programador. Depende de config y profile.
- `packages/complementairy/src/dialogo.ts`: (sin resumen)
- `packages/complementairy/src/doctor.ts`: Diagnostica el entorno verificando disponibilidad de Node, git, credenciales de Claude, hooks, documentación y herramientas del stack detectado, sin modificar nada a menos que se indique. Depende de adapters, config y profile.
- `packages/complementairy/src/files.ts`: Lista archivos del proyecto respetando .gitignore mediante `git ls-files` o fallback a escaneo manual si no hay repositorio. Depende de config.
- `packages/complementairy/src/gate.ts`: Ejecuta verificación determinista (tipos, lint, tests, mutation testing, reglas mecánicas) mediante herramientas reales sin intervención de IA en la decisión de aprobación. Depende de adapters y config.
- `packages/complementairy/src/guard.ts`: Valida respuestas de IA mediante reglas deterministas: controla nivel de código permitido, detecta si reutiliza identificadores del usuario y rechaza soluciones copiables. Depende de parser y render.
- `packages/complementairy/src/guia.ts`: (sin resumen)
- `packages/complementairy/src/hook.ts`: (sin resumen)
- `packages/complementairy/src/init.ts`: (sin resumen)
- `packages/complementairy/src/lang.ts`: (sin resumen)
- `packages/complementairy/src/llm.ts`: Puerta única hacia la IA con llamadas independientes sin historial compartido, herramientas solo lectura y validación JSON estructurada. Registra consumo (tokens, costo, ms) en ~/.cai/uso.jsonl y permite desactivar razonamiento o herramientas para respuestas rápidas y baratas.
- `packages/complementairy/src/memoria.ts`: Parsea y mantiene la memoria del proyecto (.cai/conocimiento.md) con preguntas respondidas, abiertas y notas del usuario. Filtra sin IA las preguntas sobre código que se resuelven leyendo archivos.
- `packages/complementairy/src/metricas.ts`: (sin resumen)
- `packages/complementairy/src/modos.ts`: Define dos modos de trabajo (programar/aprender) que cambian comportamiento: escalera de ayuda, snippets sin intento, predicciones y explicación. Elige el modo efectivo por función, archivo, carpeta o proyecto (gana el más específico).
- `packages/complementairy/src/notas.ts`: Guarda notas de la IA separadas del código (.cai/notas/<archivo>.json) con auto-reancla por texto y función. Persiste hilos, snippets, predicciones, verificaciones y explicitaciones, archivando resueltas viejas.
- `packages/complementairy/src/notasFuncion.ts`: Crea una nota por función y una por archivo (no duplica) agrupando todo lo que se dice de esa función. Consolida notas abiertas de la misma función en la más vieja sin perder mensajes ni snippets.
- `packages/complementairy/src/ocupado.ts`: Bloqueo por archivo (.cai/cache/ocupado/) que evita dos pedidos simultáneos y muestra qué hace la IA. Auto-limpia bloqueos de procesos muertos después de 15 minutos, permite reentrancia del mismo proceso.
- `packages/complementairy/src/panorama.ts`: (sin resumen)
- `packages/complementairy/src/parser.ts`: (sin resumen)
- `packages/complementairy/src/plano.ts`: (sin resumen)
- `packages/complementairy/src/planoArchivo.ts`: (sin resumen)
- `packages/complementairy/src/predict.ts`: Sistema de predicción: la IA propone llamadas a tus funciones, vos predecís el resultado sin ejecutar, y se compara contra la ejecución real del código. Depende de: comments, config, lang, llm, profile, render, notas, threads, tutor, verify.
- `packages/complementairy/src/profile.ts`: Registra el nivel de dominio del programador en cada tema (lenguaje, librería) con puntaje auditable. Vive en ~/.cai, es editable y cada cambio queda en eventos.jsonl. Depende de: fs, os, path.
- `packages/complementairy/src/rapida.ts`: Proporciona una guía corta de una línea mientras se escribe una función, indicando el siguiente paso o un error en la línea actual del cursor, siguiendo los pasos de la nota si existen. Depende de config, langFor, ask (LLM), cargarNotas, funcionesDe, modoEfectivo, verificar y tutor; implementa caché por código+línea con límites de espera entre sugerencias y tope de llamadas por hora.
- `packages/complementairy/src/render.ts`: Convierte respuestas de IA en comentarios formateados del lenguaje, con soporte para snippets, listas y links respetando indentación. Depende de: comments, lang, verify.
- `packages/complementairy/src/responder.ts`: Gestiona la conversación dentro de una nota respondiendo a pedidos de ayuda (pista, pseudocódigo, tests, explicación, etc.) con respuestas estructuradas según el nivel del programador y el modo (escalera o directo), además de ubicar snippets sugeridos en el código. Depende de biblioteca, comments, config, context, guard, langFor, ask (LLM), metricas, cargarNotas, notasFuncion, modoEfectivo, ocupado, predict, profile, render, salida, tests y tutor.
- `packages/complementairy/src/review.ts`: Orquesta la revisión de código en dos fases: sensores deterministas que bloquean, luego revisores de IA enfocados en paralelo (bugs, seguridad, simplicidad, tests, convenciones, arquitectura), consolidando hallazgos y ejecutando «Otra mirada» (revisión ciega sin ver código). Depende de gate (verificaciones), llm (IA), config (contexto), parse (comentarios), profile (nivel del programador) e inserta resultados como comentarios o notas.
- `packages/complementairy/src/salida.ts`: Punto único de salida para todos los aportes de la IA: agrupa por función/tipo, convierte a markdown con etiquetas y snippets, e inserta como notas (sin tocar archivo) o comentarios (en disco o como ediciones para el editor). Depende de parse (comentarios), lang (lenguajes), notas (persistencia) y render (formateo).
- `packages/complementairy/src/selftest.ts`: Suite de pruebas que valida las garantías de seguridad de ComplementAIry: verifica que el sistema permita solo comentarios @guia y cambios no invasivos, mientras bloquea ediciones de código, creación de archivos sin autorización y comandos shell peligrosos. Depende de más de 30 módulos del proyecto que cubren notas, hooks, control de acceso, verificación, guías interactivas y validación de expresiones.
- `packages/complementairy/src/servir.ts`: Proceso de larga vida que actúa como servidor para la extensión de Claude Code: recibe pedidos JSON por línea en stdin y responde sugerencias rápidas sin modificar archivos. Depende de configuración, gestión de sesiones, llamadas LLM y respuestas rápidas locales.
- `packages/complementairy/src/sesion.ts`: Gestor de sesiones del proceso abierto de Claude Code que optimiza respuestas cortas reutilizando una sesión entre múltiples pedidos, con reinicio automático tras N usos o inactividad prolongada, y fallback a llamadas normales si hay timeout. Depende del SDK de Anthropic, gestión de LLM y manejo de promesas con control de aborto.
- `packages/complementairy/src/siguiente.ts`: Determina el siguiente paso sin IA ordenando tareas por prioridad: respuestas pendientes, verificaciones fallidas, tareas del plano y notas. Gestiona diagnósticos, tareas y su marcado automático según estado del código. Depende de: parse (comments), dataDir/makeZoner (config), listFiles (files), langFor (lang), medir (metricas), todasLasNotas (notas), leerMemoria (panorama).
- `packages/complementairy/src/snapshot.ts`: Red de seguridad que fotografía el proyecto antes de comandos de ComplementAIry y revierte cambios no permitidos, guardando lo revertido en cuarentena. Verifica según políticas de zona (humana, snippets, datos) y comandos permitidos. Depende de: dataDir/Zoner (config), listFiles (files), parseMemoria (memoria), snippetPolicy (snippets), langFor (lang), verifyCommentOnly (verify).
- `packages/complementairy/src/snippets.ts`: Gestiona plantillas de VSCode (snippets) según política configurada del proyecto, permitiendo crear snippets a partir de código existente del programador sin intervención de IA. Depende de la configuración, el perfil del usuario y funciones de identificación de lenguaje.
- `packages/complementairy/src/state.ts`: Persiste en caché el estado de conversaciones dentro del código (nivel alcanzado, región, temas) para cada hilo identificado por archivo e ID. Depende del sistema de archivos para lectura/escritura de JSON.
- `packages/complementairy/src/terminal.ts`: Actúa como tutor interactivo que explica comandos antes de ejecutarlos, detecta riesgos, responde preguntas con ayuda gradual y explica errores; nunca ejecuta comandos. Depende de configuración, contexto del proyecto, LLM y perfil del usuario.
- `packages/complementairy/src/tests.ts`: Propone casos de prueba mediante IA para que el programador los revise, prueba casos contra el código sin escribir archivos, y genera tests con casos activables. Valida llamadas determinísticamente y calcula imports automáticamente. Depende de: parse (comments), makeZoner (config), contextBlock/projectContext (context), langFor (lang), ask (llm), rutaTest (metricas), ejecutar/exportedFunctions/validarExpresion (predict), renderReply (render), iaOpts (tutor), verifyCommentOnly (verify).
- `packages/complementairy/src/threads.ts`: Extrae y estructura conversaciones IA-programador del código parseando comentarios especiales (@ia?, @guia, @yo:); calcula regiones y hashes para detectar cambios sin estado oculto. Depende del parser de comentarios y análisis sintáctico del árbol de código.
- `packages/complementairy/src/tutor.ts`: Implementa el sistema de guía progresiva que procesa consultas @ia? del código, agrupa hilos de conversación y genera respuestas escalonadas (pistas → piezas → pasos → ejemplos) según el nivel del programador y la zona del archivo. Depende del perfil del usuario (profile.js), estado de hilos (state.js), parseo de comentarios (comments.js), contexto del proyecto (context.js), biblioteca de snippets (biblioteca.js) y llamadas a la IA (llm.js).
- `packages/complementairy/src/verificar.ts`: Valida si una función completada cumple su objetivo: primero ejecuta verificaciones rápidas sin IA (sintaxis, tipos, lint), y si pasa, consulta a la IA para revisar requisitos, casos borde y bugs. Soporta verificación con un plan ciego o con la explicación del programador. Depende del parseo (comments.js), medición de funciones (metricas.js), gestión de notas (notas.js, notasFuncion.js), verificaciones rápidas (gate.js) y llamadas a la IA (llm.js).
- `packages/complementairy/src/verify.ts`: Valida que toda modificación al código respete la regla central: solo se pueden agregar o cambiar comentarios @guia que ocupen líneas completas o el final de una línea, dejando código y comentarios del humano intactos byte a byte. Depende de parsing de comentarios (comments.js) y especificaciones de lenguaje (lang.js), y neutraliza directivas de herramientas en el texto de respuestas.
- `packages/complementairy/src/watch.ts`: Monitorea cambios en el proyecto en tiempo real y dispara automáticamente respuestas a preguntas @ia? o @yo: sin responder, con debounce de 700ms para evitar procesamiento múltiple. Depende de config.js, detección de lenguaje (lang.js) y el motor de acompañamiento (acompanante.js).
- `packages/vscode-complementairy/src/acciones.ts`: Gestiona la inserción de snippets desde notas en el código del editor, mostrando previsualizaciones visuales y permitiendo al usuario elegir dónde insertarlos. Depende de la API de VSCode, utilidades comunes, y la vista de notas.
- `packages/vscode-complementairy/src/codelens.ts`: Muestra información visual (lentes de código) sobre cada función, incluyendo notas asociadas, ayuda disponible y estado de verificación. Depende de la API de VSCode, utilidades comunes y la vista de notas.
- `packages/vscode-complementairy/src/comun.ts`: Centraliza todas las utilidades compartidas entre módulos: comunicación con la CLI, lectura de notas y configuración del proyecto, manipulación de tipos e interfaces, y gestión de modos de trabajo. Depende de APIs de Node.js (fs, path, execFile) y VSCode.
- `packages/vscode-complementairy/src/configuracion.ts`: (sin resumen)
- `packages/vscode-complementairy/src/estado.ts`: (sin resumen)
- `packages/vscode-complementairy/src/extension.ts`: Punto de entrada de la extensión de VSCode que expone la CLI `cai` como comandos, decoradores visuales y paneles integrados. Depende de módulos internos (acciones, codelens, notaView, panel, estado, rapidas) que orquestan la invocación de la CLI como subproceso para análisis, acompañamiento y pruebas de código.
- `packages/vscode-complementairy/src/notasView.ts`: Gestiona la visualización e interacción de notas (comentarios IA-humano) en VS Code mediante hilos nativos o panel lateral, con decoraciones en margen, botones de pedidos predefinidos e integración de comandos. Depende de VSCode API, módulos comunes (guardar, correr, leer notas) y `notaView` para el panel de lectura.
- `packages/vscode-complementairy/src/notaView.ts`: Implementa un panel webview en VS Code que muestra dinámicamente la nota de la función bajo el cursor, con estado, acciones, botones y caja de conversación, permitiendo elegir tareas o preguntas desde el panel lateral. Depende de módulos internos (comun, acciones, notasView), la API de VS Code, y lee archivos parcialmente escritos por la CLI para mostrar respuestas de IA en vivo.
- `packages/vscode-complementairy/src/panel.ts`: Implementa un árbol de datos (TreeDataProvider) que muestra un panel lateral en VS Code con el estado del proyecto: pasos pendientes, tareas, estructura, preguntas abiertas, notas por archivo y actividad de la IA. Depende de la CLI (`cai siguiente/tareas/memoria --json`), del módulo `comun` para ejecutar comandos y leer el proyecto, y de archivos JSON en `.cai/` que almacenan la estructura y panorama.
- `packages/vscode-complementairy/src/rapidas.ts`: Genera sugerencias rápidas (pistas inline en gris) mientras escribes dentro de funciones, manteniendo un proceso `cai servir` abierto para responder en ~1s en lugar de ~20s por llamada. Depende del módulo `comun` para acceder a configuración y al proyecto, de VS Code API para decoraciones de editor, y de la CLI con los comandos `servir` y `rapida`.
- `scripts/feature.sh`: Empaqueta ComplementAIry compilando la CLI y la extensión de VSCode para distribuirlo como una feature de devcontainer. Depende de pnpm/npm y de los paquetes en `packages/complementairy` y `packages/vscode-complementairy`.
- `scripts/instalar.sh`: Instala la CLI `cai` globalmente y la extensión de VSCode desde el código fuente del repositorio. Depende de npm/pnpm, Node.js y opcionalmente del comando `code` de VSCode.
